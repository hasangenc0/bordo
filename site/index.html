Bordo
GitHub

One sentence in. A running service out.

Bordo scaffolds the project, builds the image in GitHub Actions, and deploys it to a server you own. You get a URL back. Self-hosted, driven by an agent or a few CLI commands.

you   › create a java web service called hello-api and ship it
bordo › ✓ scaffolded hello-api from java-web-service
        ✓ image built in GitHub Actions, pushed to GHCR
        ✓ deployed to k3s on your server
        ✓ live at http://your-server:3xxxx/
Install in 5 minutes Source on GitHub

What you get

No platform team needed

No Dockerfiles, Kubernetes manifests, or CI YAML to write. Templates carry the defaults.

Runs on a $5 VPS

One Linux box with Docker is enough. Bordo installs k3s for you.

Builds stay off your server

Images build in GitHub Actions and publish to GHCR, so the server only runs them.

Multi-region

bordo region add prints one command. Run it on another machine and it joins the fleet.

No keys left lying around

Servers join with a one-time token. The control plane stores no SSH keys and no cluster-admin credentials. Each cluster pulls its own config.

Observability included

OpenTelemetry, VictoriaMetrics, Loki and Tempo. Ask the agent for logs or a rollback.

Install

You need a Linux server you can SSH into, with Docker installed.

curl -fsSL https://raw.githubusercontent.com/hasangenc0/bordo/master/install-cli.sh | sh
bordo setup

bordo setup installs and starts Bordo, reads the setup token for you, asks for a DeepSeek API key, then shows a short code to enter at GitHub. Prefix the install with BORDO_SETUP=1 to run setup right after it, or pass --deepseek-key and --skip-github to script it.

Then ship something:

bordo agent chat
› create a java web service called hello-api and build it
› deploy hello-api and expose it to the internet

Prefer plain commands?

bordo project create hello-api --template java-web-service
bordo build trigger hello-api
bordo deploy create <project-id> <image> --region <region> --expose nodeport

For HTTPS on your own domain, deploy with --expose ingress --host app.yourdomain.com.
